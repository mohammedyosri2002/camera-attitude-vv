# Data Provenance

Every file in this repository is classified below. Nothing was fabricated; nothing was
silently cleaned up; history was not rewritten.

## B. Files generated during the original analysis

- `data/raw/*/motor_clockfit.json` — clock fit written by the serial logger at run time.
  Retained for provenance. The reproduction pipeline **refits** from the event log rather
  than trusting it.
- `data/raw/*/camera_*_meta.json` — acquisition metadata written by the camera program,
  including the board layout in force at acquisition time. For RUN05 that layout was the
  **stale Board-X one**, which is why RUN05 is reprocessed.
- `data/raw/*/prebias_meta.json` — commanded pre-position record written by the logger.

## D. Offline RUN05 reprocessing artefacts

RUN05 was acquired with the **stale Board-X layout**. Its logged pose columns are invalid
and are ignored entirely. The pose is re-solved for every one of its 67 436 frames from the
stored raw AprilTag corner pixels using
`config/board_geometry_boardY_bundle_adjusted.json`.

That layout was obtained by bundle adjustment of the logged corner pixels, with the tag
size held fixed at 0.070 m. It is **camera-derived** and is not an independent dimensional
reference — see [`docs/GEOMETRY.md`](docs/GEOMETRY.md).

Board-X runs are also re-solved from raw corners. With the undistorted intrinsic matrix
and the acquisition reference construction this reproduces their logged acquisition
attitude to 0.000000 deg, so nothing changes by doing so and every out-of-plane run is
processed uniformly. Each run declares `pose_source` in `RUN_INFO.json`.

Reprocessing outputs (`results/board_y.json`, `results/board_x.json`,
`results/yaw.json`, `results/reproduced_numbers.json`, `results/VERIFICATION_REPORT.md`,
`results/tables/`, `results/figures/`) are regenerated by the pipeline and are not primary
data.

## D2. Intrinsic-matrix correction: the correction that changed the Board-Y numbers

The acquisition program **undistorts every frame before detection**:

```
newK, _ = cv2.getOptimalNewCameraMatrix(CAMERA_MATRIX, DIST_COEFFS, (w,h), 1, (w,h))
m1, m2  = cv2.initUndistortRectifyMap(CAMERA_MATRIX, DIST_COEFFS, None, newK, ...)
und     = cv2.remap(frame, m1, m2, cv2.INTER_LINEAR)
tags    = detector.detect(und, ...)
sol     = solve_board(O, I, newK, R_prev)
```

The corner pixels in the camera CSV are therefore in **undistorted image coordinates**, and
the matrix that belongs with them is `newK` - **not** the raw `camera_matrix` stored in the
metadata. On this rig that is a **7.54 % focal-length difference**: fx 1443.25 versus
1334.37.

The first offline pipeline used the raw `camera_matrix`. It did not fail loudly: the pose
still solved on 100 % of frames with zero branch flips, board reprojection rose only from
about 0.28 px to 0.37 px, and the recovered angles shifted by a few tenths of a degree.

`analysis/board_x/audit_board_x_reference.py` isolated it. With `newK` **and** the
acquisition reference construction, offline re-solution of a Board-X run reproduces the
logged acquisition attitude to **0.000000 deg** (maximum sample-wise difference over
44 591 frames) and reproduces the submitted 0.2678 deg exactly.

**Consequence.** Board-X and yaw values are unaffected - the acquisition itself used `newK`
correctly, and those submitted numbers came from the acquisition. **The Board-Y (RUN05)
values were affected**, because RUN05 had to be reprocessed offline (it was acquired with
the stale Board-X layout) and that reprocessing used the wrong matrix:

| Board-Y metric | As submitted (superseded) | Corrected |
|---|---|---|
| static camera - commanded RMSE [deg] | 0.2987 | **0.2539** |
| static camera - commanded Bias [deg] | 0.2814 | **0.2186** |
| static camera - commanded MAE [deg] | 0.2826 | **0.2212** |
| static camera - gravity RMSE [deg] | 0.2641 | **0.2164** |
| dynamic camera RAW rate RMSE [deg/s] | 1.3117 | **1.3004** |
| rate-scale range [percent] | -0.47 to +0.75 | **-1.39 to -0.17** |
| board reprojection median [px] | 0.3676 | **0.2815** |
| hinge axis | (-0.03299, +0.99931, -0.01695) | **(-0.03494, +0.99926, -0.01625)** |

The corrected board reprojection is **lower** (0.2815 px versus 0.3676 px), which is
independent evidence that `newK` is the physically correct matrix for these corners.

`results/verified_numbers.json` carries the corrected values under `board_y` and preserves
the originals under `board_y_AS_SUBMITTED_SUPERSEDED` for traceability. **The superseded
values must not be used in the paper.**

## D3. RUN05 board-layout refit

### Board-Y revision history

The Board-Y figures were revised twice during the final audits. Both causes were the same
underlying issue: the acquisition undistorts every frame before detection and solves with
`newK` from `getOptimalNewCameraMatrix`, so the stored corner pixels are in **undistorted**
image coordinates and `newK` — not the raw `camera_matrix` — is the matrix that belongs
with them (fx 1334.3666 versus 1443.2497, a +8.16 % difference).

| Revision | Intrinsics for pose | Intrinsics behind the board layout | static camera − commanded RMSE [deg] | board reprojection median [px] |
|---|---|---|---|---|
| as submitted | raw `camera_matrix` | raw `camera_matrix` | 0.2987 | 0.3676 |
| intermediate | **newK** | raw `camera_matrix` | 0.2539 | 0.2815 |
| **final** | **newK** | **newK** | **0.2918** | **0.2620** |

`analysis/board_y/refit_board_y_geometry.py` established conclusively that the original
layout file had been fitted with the raw matrix: refitting with the raw matrix reproduces
the stored file to **0.0000 mm**, while refitting with `newK` moves tag centres by up to
**0.4817 mm** and rotations by up to
**0.2358 deg**. The corrected refit lowers the bundle RMS
from 0.3559 px to
**0.2583 px**, and the final full-run board reprojection
falls to 0.2620 px with the minimum
second-to-selected reprojection ratio rising to 10.931. Both
improvements are independent evidence that `newK` is the physically correct matrix.

Superseded values are preserved in `results/verified_numbers.json` under
`board_y_AS_SUBMITTED_SUPERSEDED` and `board_y_SUPERSEDED_rev2_rawK_geometry`, and the
superseded layout as `config/board_geometry_boardY_bundle_adjusted_rawK_SUPERSEDED.json`.
**None of them may be used in the paper.** Board-X and yaw are unaffected throughout:
their submitted values come from the acquisition, which used `newK` correctly, and they
reproduce exactly.

## Integrity

`data/MANIFEST.csv` and `data/CHECKSUMS.sha256` cover every included raw file.
`python analysis/reproduce_all.py` verifies all checksums before doing anything else and
exits 2 on mismatch.

Every run: expected serial event count present (114 out-of-plane, 94 yaw), `RUN_END`
received, monotonic timestamps on all three clocks, and no controller reset between the
commanded pre-position and the profile start.
